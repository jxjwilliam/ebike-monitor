# 电单车平台：架构与技术栈规格

日期：2026-10-30；状态：建议架构。服务依据见 [研究记录](oc_05_china_services_research.md)。

## 1. 架构决策

采用模块化单体业务 API，加独立异步识别 Worker。当前规模的主要难点是采集可靠性和证据可比性，不需要先拆微服务、建设数据湖或引入 Kubernetes。业务逻辑与识别运行环境分别发布，避免模型依赖拖累 API。

```text
管理后台 Vue 3 / 采集 H5 / 后续 Android 辅助端
                    │ HTTPS + 项目权限
              Nginx → FastAPI 业务 API
                    ├─ 点位/区域/任务/复核/交付/审计
                    ├─ PostgreSQL + PostGIS：事实、状态、版本、Outbox
                    ├─ OSS 私有桶：原图、接口原始响应、派生图、导出包
                    └─ Outbox 派发 → RabbitMQ → Celery Worker
                                                ├─ 文件与时空质检
授权数据源适配器 → 原始证据入库                   ├─ OpenCV / PaddleOCR
                                                ├─ 专用图标检测模型（可选）
                                                └─ 人工复核 / 境内视觉模型（可选）
监控、日志、审计 → 站内异常队列 → 钉钉通知（可选）
```

## 2. 推荐技术栈

| 层 | 首选 | 理由与边界 |
| --- | --- | --- |
| 管理端 | Vue 3、TypeScript、Vite、Element Plus、ECharts | 表格、审核与地图交互；依赖和字体本地打包 |
| 采集端 | 首期响应式 H5；二期 Kotlin Android | H5 降低安装成本；原生端用于授权录屏、离线队列和设备预检 |
| 地图 | 高德 JS API 2.0，企业项目 Key | 展示点位和业务区域；不提供三品牌车辆库存 |
| API | Python 3.12、FastAPI、Pydantic、SQLAlchemy、Alembic | 与图像任务统一语言；具体包版本在 PoC 锁定 |
| 主库 | PostgreSQL 16、PostGIS，生产采用 RDS 支持版本 | 关系数据、版本和区域查询；购买前核对扩展兼容矩阵 |
| 异步 | Celery＋RabbitMQ，数据库 Outbox | 重试、隔离慢任务；状态以数据库为准，不以队列为准 |
| 图像处理 | OpenCV、PaddleOCR；按需评估 PaddleDetection | OCR 读时间、比例尺与提示文字，检测模型识别车辆图标；二者不是同一任务 |
| 辅助视觉 | 阿里云百炼支持境内推理的视觉模型；或境内部署的开放权重模型 | 仅给建议，锁定模型与提示词版本；不生成无证据的真实流量 |
| 存储与密钥 | OSS、RAM/STS、KMS | 私有证据、短期访问凭证和密钥轮换 |
| 部署 | 国内 Linux、Docker Compose、Nginx、阿里云 ECS | 先做可恢复的少量节点部署，生产按故障域拆分 |
| 可观测性 | 应用结构化日志＋Prometheus/Grafana 或阿里云日志服务 | 先任选一套主监控，避免重复建设 |
| 工程验证 | pytest、前端组件测试、Playwright | 覆盖核心业务规则和整条交付链路 |

以上是可在国内运行的开源与国内托管服务组合，不是“全国产软件栈”声明。首期不引入 Redis；有明确缓存需求再加，避免把缓存做成任务事实来源。

## 3. 三种数据入口

### A. 授权结构化接口：长期优先

品牌方、城市管理方或有权供应商提供车辆位置/事件接口或定时文件。接口是否存在、商业可用性、三品牌覆盖均待商务验证。适配器声明 `snapshot_only`、`stable_vehicle_id`、`event_stream` 等能力；凭有 ID 的两端快照仍不能声称完整真实流量。

### B. 现场截图上传：MVP 必备

采集人员打开三家官方 App，按 SOP 截图后选择任务上传。系统提示每轮应采内容、时间误差和边界参考。原图、圈选图、人工现场计数分开存储。该模式可以先打通业务，但不保证单设备手动切换能达到三品牌 30 秒同步目标，必须实测。

### C. Android 辅助采集：条件性二期

在受控真机上使用系统授权的 MediaProjection 进行采集辅助，每个会话需用户同意，遵守前台服务与目标 App 限制。它不自动完成登录、地图定位、切换三品牌、稳定刷新或消除遮挡。原生 App 仅作为采集助手，不能默认为全自动机器人。

先验证单设备切换；达不到同步目标时，可试验一品牌一设备并行。后者也需要验证定位、账号、网络、时间和权限，不能只按设备数推断可用性。Android 方案不自动覆盖 iOS 或 HarmonyOS NEXT；各系统单独评估。

不把模拟定位、私有协议逆向、风控绕过或账号池写为默认生产依赖。用户设备的录屏同意也不能代替平台数据使用授权。授权或稳定性不足时保留人工路径，相关品牌指标显示覆盖不足。

## 4. 时空与识别流水线

1. 上传后先验文件类型、大小、解码和 SHA-256；保留原始文件。
2. OCR 提取平台、时间、文字提示与比例尺；屏幕时间不含日期或仅显示分钟时，不当作精确可信时间。
3. 配准地图稳定地物，剔除车辆、提示框等动态元素；检查缩放与漂移。没有足够控制点时拒绝自动配准。
4. 根据经确认的地物控制点、地图视口元数据或授权坐标确定业务 ROI。不能仅凭图像宽高推导真实 100 米区域。
5. 图标检测区分车辆、停车点 P、禁停标识及定位图标；给出框与数量建议。重叠无法拆分时进入人工标注。
6. 可比较的两端计算净变化；端点匹配单列；真实流量必须依赖独立事件/现场连续证据。
7. 人工复核保留模型建议和修订，批准后生成不可变结果版本。

地图 GCJ-02 原始数据带坐标标签保留。不能 `ST_SetSRID(...,4326)` 就声称完成转换。PoC 内在 GCJ-02 一致的局部坐标空间进行 ROI 相交判断，几何列使用 SRID 0 并另存 `coord_sys`，不冒充 WGS84。100 米尺寸构造采用经验证的局部米制近似，并记录算法版本与误差；如果验收精度不满足，则接入有授权的专业坐标处理方案。跨坐标数据未经验证转换不得混算。

## 5. 调度与可靠性

数据库保存每个计划槽位，调度器用租约和行锁认领；队列只传 ID。定期扫描未派发 Outbox 和超时任务，Worker 使用数据库唯一键实现幂等。图像处理可重放，历史采集不可重放。

- 采集任务记录 `scheduled_at/deadline_at`，过期即标记漏采；后来的图片另存为迟到证据。
- 同一槽位保留多个 attempt，但只能有一个获批主证据；不覆盖失败或被替代的记录。
- 外部 API 使用授权配额内的限流、超时和退避；过期重试不能伪装为准时快照。
- API、识别、导出使用分离队列；推理失败不会阻塞上传和人工复核。
- 数据库提交与队列发送使用 Outbox 避免双写丢失；任务消费按至少一次设计。

## 6. 国内部署与运行

PoC 可在一个国内 ECS 上用 Compose 运行 API、数据库、消息队列与 CPU Worker；OSS 使用国内地域。生产将 RDS、消息队列、API 和 Worker 分开部署，API 至少两副本经负载均衡接入；RabbitMQ 使用托管服务或经过验证的高可用集群，不把单节点当高可用。

默认主业务地域建议杭州或北京，依据人员访问与资源可用性实测选择；备份放中国内地另一个故障域。数据库不开放公网，管理访问走受控运维通道。镜像、模型、npm/Python 包、字体和前端静态资源提前同步到国内可信仓库，记录版本、校验值和许可证，运行时不依赖海外 CDN。

百炼必须核实**所选模型的服务部署范围**，不能只检查 `cn-beijing` 域名。若模型不能满足“仅境内推理”，则禁用云端视觉，使用本地模型或人工复核，不自动切到境外服务。

建议生产目标：API 月可用性 99.5%、业务库 RPO≤1 小时、RTO≤4 小时；由备份策略和恢复演练证明。已确认上传成功的证据必须可追溯；API 可用性不能替代采集准时率。原图建议保存 180 天、结果与审计 1 年，均为待合同确认的初始设置，删除需联动交付引用与保留要求。
