# 电单车采集与核验平台：产品规格

版本：0.1；日期：2026-10-30；状态：待评审。原始要求及来源见 [索引](oc_00_readme.md)。

## 1. 目标与边界

让项目负责人按城市、点位、时段创建任务，现场人员提交三品牌证据，系统辅助计数、人工复核，最终输出可追溯的数据包。MT、DD、HB 分别作为美团、滴滴青桔、哈啰的内部品牌代码，品牌显示名由业务确认。

第一版提供点位导入、任务排班、人工上传、自动质检、辅助计数、人工修订和 Excel/CSV 交付。不以未取得的品牌接口为前提；不承诺静态截图可以恢复完整真实事件。高密度车辆、严重遮挡和无法配准的画面进入人工复核或不可判定状态。

## 2. 角色与页面

| 角色 | 操作范围 | 主要页面 |
| --- | --- | --- |
| 项目负责人 | 本项目计划、点位、任务分配、验收与发布 | 项目总览、地图、任务表、交付中心 |
| 采集人员/供应商 | 仅分配给自己的任务及证据 | 移动任务清单、采集指引、上传与异常上报 |
| 复核员 | 分配的证据、标注和修订 | 三品牌七轮对照、区间对照、争议队列 |
| 客户查看者 | 已发布数据与获准查看的证据 | 结果查询、下载 |
| 平台管理员 | 账号、权限、运行配置 | 管理与审计 |

所有权限在 API 层按组织、项目和任务校验。修改者与最终批准者应分离，供应商不得自行批准自己的交付。

## 3. 任务与采集规则

- 一次 Session＝一个项目、点位版本、采集日期、时段、监控区域版本；包含三个 BrandRun。
- 一轮 Round＝`T+600×k 秒`，`k=0..6`。一个 Session 应有 21 个有效品牌时点。
- 所有排班按 `Asia/Shanghai`；接口时间必须带偏移，数据库保存 UTC。
- **建议初始容差**：每次采集距计划时刻不超过 ±30 秒；同一轮三品牌实际采集时间极差不超过 30 秒。分别检查，均可按项目配置；实际可达性由 PoC 验证。
- 保存计划时间、实际采集时间、接收时间和来源刷新时间。刷新时间未知时填空，不以上传时间替代采集时间。
- 同品牌七轮地图边界和比例尺保持一致；三品牌覆盖同一业务区域。画面能否证明完整覆盖，比取景框外观是否相似更重要。
- 首轮圈选作为派生标注保存，不能覆盖原图。围栏、现场可见区和正式监控区域分别管理。
- 运营区外、网络失败、无法登录、图标遮挡、画面漂移和错点位均为明确异常；不得用 0 代替无数据。

移动端第一版采用 H5 手动上传截图和任务绑定。H5/小程序不能作为跨 App 自动截图工具。离线上传保留设备时间与校时信息，无法验证实际采集时间的文件进入时间不确定状态。

## 4. 指标口径

| 指标 | 定义 | 证据要求 |
| --- | --- | --- |
| `platform_visible_count` | 指定时刻区域内平台展示的可辨识车辆数 | App 图像或授权接口；不得直接称现场总库存 |
| `physical_count` | 现场观察的实际车辆数 | 人工或现场视频，单独记录 |
| `net_change` | 期末有效车辆数减期初有效车辆数 | 同来源、同区域、可比的两个时点 |
| `endpoint_in/out` | 两端可靠匹配后，仅末端/仅首端存在的车辆数 | 稳定匿名 ID 或充分验证的匹配；仅称端点变化 |
| `gross_in/out` | 区间 `(start,end]` 内实际跨越业务边界的事件数 | 覆盖完整时段的可靠事件流或现场连续证据 |
| `suspected_dispatch_in` | 有补车迹象的流入车辆数 | 规则版本、片段/记录、人工复核；无法计辆时只记录事件 |

十分钟内进入又离开的车辆不会被两端快照完整记录。更高频轮询也只是缩小漏检窗口，不自动升级为完整事件流。持续录制 App 地图仍反映平台刷新后的显示，不等同现场连续视频。

`suspected_dispatch_in` 是同口径总流入的子集，不再加一次。没有调度出证据就不猜测调度出；不因为数量突增直接确认运维补车。

示例：20 辆变为 20 辆，仅能直接确定净变化为 0；真实流入流出应为 `null`，除非有独立事件证据。每个结果显示 `method`、`status` 和证据，未知与真实零严格区分。

## 5. 主流程与验收

点位导入预检 → 确认中心及区域 → 创建任务 → 人员/设备预检 → 七轮采集 → 文件与时空质检 → 自动建议 → 人工复核 → 批准 → 发布不可变交付版本。

允许发布“部分完成”报告，但必须显示计划值、有效值、缺失值和缺失原因，不能显示“全部合格”。拒收的证据保留原因，可补传新版本；补拍不能补回已经过去的历史时刻。

以下是建议验收门槛，不是现有算法成绩：

| 项目 | 建议门槛 |
| --- | --- |
| 证据与追溯 | 每个发布值均可定位原始证据、区域、时间、方法和批准记录 |
| 采集完整率 | 有效时点/冻结后的应采时点 ≥99%；取消任务单列，不事后缩小分母 |
| 计数 | 在盲测可判定样本中，绝对误差 ≤1 辆的比例 ≥95%，分品牌与密度报告 |
| 自动覆盖率 | 同时报出自动可判定样本/全部样本比例；计数准确率不能隐藏拒答比例 |
| 真实流量 | 仅在有连续真值的独立测试集上评估；区间计数 MAE ≤1 辆/方向，事件 F1 ≥0.90（暂定） |
| 调度 | MVP 全部人工确认“疑似”；暂不承诺自动判定准确率 |
| 性能 | 普通列表查询 P95 <2 秒；有效图片入库后自动处理 P95 <120 秒，人工等待另计 |

流量门槛未通过时仍可交付合格计数，但真实流量必须标记不可判定或转人工，不得以净变化代替。

## 6. 交付包

包含 `counts.csv`、`intervals.csv`、`quality_issues.csv`、`manifest.json` 和便于客户阅读的结果 Excel。规范化长表为权威数据，宽表仅用于阅读。

每条记录包括项目、Session、点位及区域版本、品牌、计划/实际时间、值、状态、方法、证据 ID 和修订版本。证据预览使用有权限校验的短时链接；清单保存稳定证据 ID、对象版本和 SHA-256，不把临时 URL 当长期证据。
